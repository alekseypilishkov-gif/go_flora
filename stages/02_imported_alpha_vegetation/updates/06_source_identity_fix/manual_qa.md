2. Проверьте SHA-256 и manifest из delivery.md. Установите только addons/go_flora из ZIP. Не заменяйте project.godot, .godot/editor/editor_layout.cfg, сцены или данные проекта.
3. Откройте указанную сцену в Godot 4.7.2. Зафиксируйте число/ID placements и существующие Sources. Не переодобряйте legacy Sources и не используйте Make Unique/Convert to Built-in.
4. Создайте новый пустой QA Set в существующем слое для новых Sources. Используйте свободный каталог и имена .tres с суффиксом qa018. Не рисуйте и не удаляйте исторические placements. До успешной проверки можно закрыть сцену без сохранения изменений QA Set; уже созданные файлы .tres при этом сохранятся отдельно.

1. Через Add Mesh / GLB / Scene… выберите fixtures/authored_plant.tscn. Запишите display_name и новый source_id в Inspector. Сохраните в свободный qa018_source_a.tres.
2. Ожидается: выбран новый Source, Inspector показывает внешний res://.../qa018_source_a.tres. Allow Scene Fallback остаётся false и Reviewed Scene Revision пустым, если владелец не одобрял именно этот Source. Недопустимая для painting сцена может быть сохранена как Source с блокировкой; исправление не меняет Resolver.
3. Создайте второй Source того же asset с тем же display_name и другим source_id/qa018_source_b.tres. В Source Diagnostics выберите каждую строку по ID/пути и нажмите Edit selected Source in Inspector. Ожидается именно выбранный объект; окно закрывается, вкладка Inspector активна. Имена могут совпадать.
4. Проверьте Static Mesh, GLB, PNG и WebP тем же способом со свободными именами. Для карточки задайте отличимые размер/threshold/region и transform. Для reviewed PackedScene используйте только отдельный QA Source и собственное явно выполненное одобрение; разрешения legacy ресурса не переносите.

## Отказы и жизненный цикл

1. Из нового Creator выберите существующий qa018_source_a.tres. Ожидается отказ до записи с предложением нового имени. Содержимое/ID/approval первого Source не меняются, дополнительная строка не появляется.
2. Повторите с существующим .tres другого типа. Также ожидается отказ. Отмена, Esc и X в Creator/диалоге Save не создают строку палитры и не оставляют блокирующее окно.
3. При реальной ошибке записи ожидается сообщение с путём и кодом. Если запись состоялась, а проверка загрузки не прошла, файл остаётся и сообщение содержит путь и причину; вручную проверьте его отдельно, не перезаписывайте Creator поверх этого файла.

## Сохранение, общий Source и совместимость

1. Добавьте ссылку на тот же qa018_source_a.tres во второй новый пустой QA Set через Set Inspector. Это должна быть ссылка на тот же файл, без Make Unique и без дублирования ID вручную.
2. Сохраните единственную рабочую сцену обычным Ctrl+S. В файловом просмотре .tscn ожидается ExtResource с путём нового Source, без отдельного SubResource-клона этого нового Source. Legacy embedded записи могут оставаться встроенными.
3. Измените только display_name/безопасный параметр нового внешнего QA Source, сохраните ресурс и сцену. Закройте и заново откройте проект/сцену. Оба QA Set должны видеть изменение одного внешнего Source, прежний source_id и approval.
4. Проверьте Undo/Redo добавления нового Source; ссылки остаются на .tres. Убедитесь, что исторические placements, их record_id/source_id/set_id/transforms и настройки раскладки не изменились. Не тестируйте Erase или массовую замену исторических записей в рамках этой приёмки.
5. Проверьте обычный Save, отсутствие ошибок thumbnail/renderer в Output. Неодобренный QA Source при enabled и положительном weight может блокировать Mix by weights по прежним правилам; для продолжения исторического painting отключите только новую QA entry или выберите проверенный Source.
